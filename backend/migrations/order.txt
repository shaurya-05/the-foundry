# Migration order — the dependency graph, stated rather than inferred.
#
# This file exists because filenames were doing double duty as an ordering
# mechanism, and the ordering they produced was alphabetical luck. `000b` and
# `000c` referenced `copilot_messages` before it existed and no fresh database
# could be built; renaming them to `006_*` fixed that particular symptom by
# arranging for `conversation` to sort before `copilot`, which is true only
# because `n` < `p`. A future `006_copilot_audit.sql` would silently reorder the
# chain and nobody would notice until a cold rebuild failed.
#
# So the order is written down. Runners read this file; they do not glob.
# `scripts/check_migrations.py` fails CI if any .sql file under migrations/ is
# missing from here, so a new migration cannot be added without also declaring
# where it belongs.
#
# Rules:
#   - one filename per line, relative to backend/migrations/
#   - blank lines and lines starting with # are ignored
#   - order in this file IS the apply order
#   - when a migration depends on another, say so in a comment above it
